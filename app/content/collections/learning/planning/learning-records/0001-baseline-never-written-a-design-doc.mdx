# Baseline — ten years of building, no design docs written

Ilango is a working full-stack engineer with about ten years' experience who
has never written a proper design doc: plans have lived in his head, tickets
and chat. Nobody at work has set a format, so he chooses. He is not starting
from a bad reviewed doc — there is no reviewed doc — so the first lessons
teach the shape and the habit, not repair.

## Implications

- Do not assume he knows the doc-type taxonomy (design doc vs RFC vs ADR vs
  POC write-up). Introduce each when it is needed, one at a time.
- He already has the engineering judgement the docs are meant to capture;
  the gap is getting it onto the page in a reviewable form. Lessons should
  spend their time on writing and self-review, not on system design itself.
- Reuse one live doc across lessons 1–3 so he finishes something reviewable
  in the first fortnight rather than three fragments.
- He asked to front-load the course, which suits the career plan's POC doc
  dates (review by 12 Sep, outcome doc by 26 Sep). If the POC doc turns out
  to be already written, the next real target is a Kobun or DocuDex feature.
