## 1. Two ways to run three small boxes (8 min)

You have three machines and want two things from them: a Kubernetes cluster
to learn on, and services that stay up. There are two sensible shapes.

**Bare Ubuntu, Kubernetes on the metal.** Ubuntu Server on each node, k3s
on top, done. One layer fewer to learn. Every byte of the 8 GB goes to
Kubernetes. The cost: the node *is* the cluster member. To try a different
Kubernetes distribution, a different OS, or to recover from a bad upgrade,
you reinstall the box with a USB stick and a monitor.

**Proxmox on the metal, Kubernetes in VMs.** Proxmox VE — a Debian-based
hypervisor with a web UI, KVM for virtual machines and LXC for containers
([admin guide](https://pve.proxmox.com/pve-docs/pve-admin-guide.html)) — on
each node. Kubernetes runs inside VMs that Proxmox creates. The cost: one more
layer, and roughly 2 GB of each node's RAM go to the host
([recommended requirements](https://pve.proxmox.com/pve-docs/pve-admin-guide.html)).
What you get: a reset button. VMs snapshot, clone, and are destroyed and
recreated from a Terraform file in minutes. Breaking the cluster becomes
routine instead of an evening lost.

For your mission — infra depth first, Terraform practice, apps as payoff —
Proxmox is the right call, and the recommendation here is Proxmox on all
three nodes with k3s in VMs. The one honest argument against it is the 8 GB:
Proxmox takes ~2 GB, a k3s server VM wants at least 2 GB
([k3s requirements](https://docs.k3s.io/installation/requirements)), and
that leaves little for the apps. The fix is a second 8 GB DDR4-2400 SO-DIMM
per node; the M710q has two slots and takes 32 GB
([Lenovo PSREF](https://psref.lenovo.com/syspool/Sys/PDF/ThinkCentre/ThinkCentre_M710_Tiny/ThinkCentre_M710_Tiny_Spec.pdf)).
Order it this week; it does not block tonight.

<Aside>

	target gets harder. Say so before you install.
</Aside>

## 2. Three facts to hold before you touch anything (5 min)

**Hostname and IP are permanent.** From the
[Cluster Manager](https://pve.proxmox.com/wiki/Cluster_Manager) docs:
each node must be "installed with the final hostname and IP configuration",
because changing either after joining the cluster is not supported. So the
name and address you type into the installer tonight are the ones the node
keeps.

**Three nodes is the right number.** Proxmox gives each node one vote and
needs a majority to write to its cluster config; lose quorum and "the cluster
switches to read-only mode". Three nodes survive one failure. Two do not,
which is why the docs offer a QDevice for two-node setups. You bought the
right count by accident.

**The installer takes the whole disk.** Two of your nodes have both a 256 GB
SATA SSD and a 512 GB NVMe. Install Proxmox on the SATA disk on every node
so all three look the same; the NVMe becomes VM storage later. The installer
lists disks by device name — the SATA drive is `/dev/sda`, the NVMe is
`/dev/nvme0n1`. Check the size shown next to it before you confirm.

### The IP plan

Your ISP router hands out addresses by DHCP. Proxmox nodes want fixed
addresses, so they live *outside* the DHCP pool but *inside* the router's
subnet — same network, no VLANs yet. Step 1 below finds the real subnet and
pool; until then this uses `192.168.1.0/24` as a placeholder. Correct it in
the [reference sheet](../reference/rack-plan) once you know.

| Device | Hostname | Address | Note |
| --- | --- | --- | --- |
| ISP router | — | `192.168.1.1` | Gateway and DNS for everything |
| TL-SG2008 | `sw1` | `192.168.1.10` | Set in lesson 2 (ships on `192.168.0.1`) |
| Node 1 | `pve1` | `192.168.1.11` | Tonight |
| Node 2 | `pve2` | `192.168.1.12` | Lesson 3 |
| Node 3 | `pve3` | `192.168.1.13` | Lesson 3 |
| Reserved | — | `.20–.49` | VMs, later |

Use `home.arpa` as the domain — it is the name reserved for exactly this
([RFC 8375](https://www.rfc-editor.org/rfc/rfc8375)) and will never collide
with a real one. So node 1 is `pve1.home.arpa`.

## 3. Hands on (90 min)

Work through these in order on your Mac and node 1. Keep a terminal open with
a file called `RUNBOOK.md` and paste every command you actually run, with the
node name — this file is what lesson 12's "rebuild in under an hour" is
measured against.

<Steps
	title="Install Proxmox on node 1"
	steps={[
		{
			title: 'Find the router’s subnet and DHCP range',
			body: (
				<>
					On the Mac, get your own address and gateway. Then log in to the ISP router (the
					gateway address in a browser) and find the DHCP settings page: note the start and end
					of the pool. Pick node addresses outside it and rewrite the IP plan above if the
					subnet is not <code>192.168.1.0/24</code>.
				</>
			),
			commands: ['ipconfig getifaddr en0        # your IP', 'netstat -rn | grep default    # the gateway'],
			check: 'You can say the subnet, the gateway and the DHCP pool out loud, and pve1’s address is outside the pool.',
		},
		{
			title: 'Download the ISO and verify it',
			body: (
				<>
					Get{' '}
					<a href="https://www.proxmox.com/en/downloads/proxmox-virtual-environment/iso/proxmox-ve-9-2-iso-installer">
						Proxmox VE 9.2-1
					</a>{' '}
					(1.71 GB) and compare the SHA256 on the download page with what you compute.
				</>
			),
			commands: ['shasum -a 256 ~/Downloads/proxmox-ve_9.2-1.iso'],
			check: 'The two hashes match character for character.',
		},
		{
			title: 'Write the USB stick',
			body: (
				<>
					The{' '}
					<a href="https://pve.proxmox.com/pve-docs/pve-admin-guide.html">admin guide</a> gives
					the macOS recipe: convert the ISO to a raw <code>.dmg</code>, find the stick with{' '}
					<code>diskutil list</code>, unmount it, then <code>dd</code> to the <em>raw</em>{' '}
					device (<code>rdiskN</code>, which is much faster). Triple-check <code>N</code> — dd
					does not ask twice. Etcher is the documented alternative if you prefer a GUI.
				</>
			),
			commands: [
				'cd ~/Downloads',
				'hdiutil convert proxmox-ve_9.2-1.iso -format UDRW -o proxmox-ve_9.2-1.dmg',
				'diskutil list                      # find the stick, e.g. /dev/disk4',
				'diskutil unmountDisk /dev/diskN',
				'sudo dd if=proxmox-ve_9.2-1.dmg bs=1m of=/dev/rdiskN status=progress',
			],
			check: 'dd finishes without error; macOS may say the disk is unreadable — that is expected, eject it.',
		},
		{
			title: 'Check the BIOS, boot the stick',
			body: (
				<>
					Plug node 1 into the switch, a monitor and keyboard. Power on and press <kbd>F1</kbd>{' '}
					for Setup (the Lenovo splash screen lists the keys if these differ). Confirm <em>Intel Virtualization Technology</em> is enabled (Proxmox needs
					VT-x) and that <em>Wake on LAN</em> is on. Save, reboot, press <kbd>F12</kbd> for the
					boot menu and pick the USB stick.
				</>
			),
			check: 'The Proxmox boot menu appears. Choose "Install Proxmox VE (Graphical)"; if the screen stays black, reboot and pick the Terminal UI installer instead.',
		},
		{
			title: 'Run the installer with the plan beside you',
			body: (
				<>
					Accept the EULA. <strong>Target disk:</strong> the 256 GB SATA drive (<code>/dev/sda</code>),
					not the NVMe. Leave the filesystem at ext4 (the default; ZFS later, when there is a
					reason). Country, timezone <code>Asia/Kolkata</code>, keyboard. Root password: 12+
					characters, into your password manager. Email: yours. <strong>Network:</strong>{' '}
					hostname <code>pve1.home.arpa</code>, IP <code>192.168.1.11/24</code> (your real
					subnet), gateway and DNS both the router. Read the summary page twice. Install.
				</>
			),
			check: 'The node reboots off the SATA disk and shows a login prompt with the URL https://192.168.1.11:8006.',
		},
		{
			title: 'Open the web UI from your laptop',
			body: (
				<>
					Unplug the monitor — you will not need it again for this node. In a browser on the
					Mac open <code>https://192.168.1.11:8006</code>, accept the self-signed certificate,
					log in as <code>root</code> with realm <em>Linux PAM</em>. Dismiss the "no valid
					subscription" dialogue; it is a notice, not an error.
				</>
			),
			check: 'You see pve1 in the left-hand tree with a green tick, and Summary shows the CPU and 8 GB (well, ~7.7 GB) of RAM.',
		},
		{
			title: 'Point apt at the no-subscription repository and update',
			body: (
				<>
					The install ships with the enterprise repo enabled, which needs a key you do not
					have. Per{' '}
					<a href="https://pve.proxmox.com/wiki/Package_Repositories">Package Repositories</a>,
					disable it and add the no-subscription one (fine for a lab; the docs say not
					production). The web UI can do it — node → <em>Updates</em> → <em>Repositories</em>,
					disable the enterprise entry, <em>Add</em> → No-Subscription — but do it by hand
					once so the runbook has the file contents.
				</>
			),
			commands: [
				'ssh root@192.168.1.11',
				"echo 'Enabled: no' >> /etc/apt/sources.list.d/pve-enterprise.sources",
				'cat > /etc/apt/sources.list.d/proxmox.sources <<EOF',
				'Types: deb',
				'URIs: http://download.proxmox.com/debian/pve',
				'Suites: trixie',
				'Components: pve-no-subscription',
				'Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg',
				'EOF',
				'apt update && apt dist-upgrade -y && reboot',
			],
			check: 'apt update reports no errors, and after the reboot the web UI comes back on its own.',
		},
		{
			title: 'Write the runbook entry',
			body: (
				<>
					In <code>RUNBOOK.md</code>: the date, the ISO version and hash, the BIOS settings you
					changed, the exact installer answers (disk, filesystem, hostname, IP), and the repo
					fix. Then the one line you will thank yourself for: what you would do differently.
				</>
			),
			check: 'Someone with the USB stick and this file could reproduce node 1 without you.',
		},
	]}
/>
